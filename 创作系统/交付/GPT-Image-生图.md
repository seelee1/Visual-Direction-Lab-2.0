# GPT Image 生图适配

适配层 v0.1 · 官方资料核对：2026-10-26。对象为 OpenAI GPT Image 系列；“GPT Image”“gptimage”均可触发本适配，不据此猜定具体 API 型号。来源为官方[提示指南](https://developers.openai.com/api/docs/guides/image-prompting)与[图像生成说明](https://developers.openai.com/api/docs/guides/image-generation)。本项目尚未直接执行 GPT Image 生图或完成受控验证；已有[用户成图观察](../../项目记录/创作案例与验证/GPT-Image-朋克风格观察/README.md)，实际模型与设置未知。

仅在用户要求 GPT Image 提示词或已明确设置该生成用途时启用。先依据核心完成艺术设计，再适配静态成稿；概念、分镜等任务仍按用户要求交付。本文件属于统一创作系统的交付层，只在对应目标明确后读取。

## 官方依据与项目约定

官方指南建议明确用途、构图和可见细节，为参考图分配职责，编辑时区分改动与保留项，画面文字给出原文与排版位置。多种提示形式均可使用，没有必须套用的标签语法。生成后仍需检查文字、身份、布局和非预期改动。[提示指南](https://developers.openai.com/api/docs/guides/image-prompting)

以下语言、段序、画幅建议和示范是本项目的交付约定，不是官方必填字段，也不是经本项目实测得到的最佳模板。

## 输出约定

默认先写一行「建议画幅：宽:高｜简短构图理由」，随后交付一个 `text` 代码块，内含可直接使用的自然语言提示词。用户已指定比例时沿用；编辑原图时默认沿用原图画幅，尚不知尺寸时写“沿用原图”，不猜比例。明确只要正文时省略建议行。

正文默认使用用户语言；用户要求英文或其他语言时遵从，画面内需要出现的文字始终保留指定原文。不默认输出双语、候选方案、艺术分析或教程。复杂作品可在代码块内用简短小标题分段，普通插画使用自然段即可，不为填结构添加内容。

本适配不设 Positive／Negative 双栏，不默认加入 `masterpiece`、`score_*`、作者标签前缀或权重语法。必要排除项写成同一提示词中的明确要求，并与画面意图一致；不套通用长串缺陷词，不自动排除作品需要的模糊、颗粒、遮挡或形变。用户提供特定平台格式时以实际规则为准。

## 将设计写成画面

按作品需要组织以下内容，不强制每次齐全：

| 内容 | 本项目的写法 |
|---|---|
| 作品与用途 | 明确生成一幅什么作品；插画、海报、角色设定或信息图各按既定设计表达 |
| 主体与空间 | 人物身份、外貌、姿态、视线、接触对象，以及景别、位置、遮挡和前后层次；多人物逐一绑定特征 |
| 光色与材质 | 写清实际光源与影形、色块关系、关键材质和相互影响，不只列氛围词 |
| 画法与重点 | 将日式二维落实在线条、轮廓、色面、边缘和细节分布；其他风格使用相应可见形式 |
| 必须保留的条件 | 原设计中让事件成立、让重点可见的构图和关系，以及当前任务的必要排除项 |

完整保留选定艺术设计和有作用的细节，不因猜测模型能力主动简化或重构，不设固定词数；删除研究解释与重复修饰即可。单幅图只写选定时刻的可见状态，不能把一连串动作或运镜伪装成同一瞬间。用户要漫画或分镜板时，说明页面布局、阅读顺序与各格状态，不自动拆成多个生成请求。

画面文字与提示词说明分开表达。需要出现的文字用引号逐项给出，并写清所在位置、层级和必要的换行；只限制额外文字时，不误删用户要求的标题、招牌或对白。信息图中的数值与关系依据用户材料，不为排版补造事实。

## 参考图与局部编辑

先依据实际附件确定每张图的角色：待编辑底图、人物身份、服装、构图、画法或场景参考。正文用“图 1”“图 2”等对应实际输入顺序，说明采用哪些特征、如何组合；编号只是交接说明，不代表图片已经上传或绑定。未看见图片时不编造其外貌；只有参考职责无法合理判断且影响结果时才澄清。

新图参考按用户希望保留的部分使用，不自动继承全部服装、背景和姿态。编辑任务明确本次修改对象、范围、目标状态及相关保留项。局部改变引起的接触、遮挡或投影也要衔接，不同时要求“改变光源”和“所有影子绝对不变”。连续修改以实际选定的上一版图片为底图，保留已确认设计，不只写“和之前一样”。

仅靠提示词不能承诺未编辑区域逐像素不变。需要严格像素保护时，应按实际工具安排局部合成；蒙版等执行材料只在实际可用时交接，不虚构已上传的文件或已完成的绑定。

## 参数与执行边界

画幅描述表达构图意图；像素尺寸、质量档、输出格式、透明背景和输入保真等参数在实际调用层设置，不能靠把参数名称写进提示词保证生效。具体型号与接口未指定时，只交付通用提示词，不硬编码 API 型号、尺寸白名单或某代专属选项。[图像生成说明](https://developers.openai.com/api/docs/guides/image-generation)

用户要透明素材时，正文说明主体轮廓和透明背景意图；执行时核对所用版本与工具的透明输出支持，并使用支持透明度的文件格式，检查实际 alpha 通道，不能把白底或棋盘格当成透明。参数、素材清单或环境限制只在需要执行交接时放在代码块外。

## 新图格式示范

以下为手工格式示范，未调用生成模型；没有输入参考图。

建议画幅：3:2｜左右安排修补者与纸灯，保留桌面支撑和窗外雨景。

```text
创作一幅日式二维叙事插画：雨天的纸灯工坊里，一位成年修灯师正在给鱼形纸灯补上一块薄纸。横向构图，以略高的三分之四视角看向工作台。

她坐在画面左侧，黑色短发拢在耳后，穿卷起袖口的灰蓝工作服。鱼形纸灯横放在右侧两个木制弧形托架上，腹部待修补的小裂口朝向她。左手隔着裂口托住里面的一根竹骨，右手把浅杏色补纸轻贴在裂口外侧，指尖停在补纸边缘。两只手、裂口与支撑位置都清楚可见，鱼形灯的眼睛和尾鳍保持完整轮廓。

后方窗户透入柔和的冷色天光，窗外雨中的屋顶以低对比色块退远。工作台左上方一盏暖色台灯照亮她的手和纸面；补纸叠层比周围纸皮略深，竹骨在薄纸下隐约可见。台灯与纸灯分开，鱼形纸灯内部没有光源。桌上只放一碟浆糊、一把平头刷和几片裁下的纸，保留大片空桌面衬托手部动作。

人物以细而有轻重变化的线条和清楚的平涂影形塑造，纸纤维与木桌只留局部轻微笔触。暖杏色纸面与灰蓝雨景形成主要色彩关系，最清晰的边缘集中在指尖、补纸和竹骨接点。不要添加字幕、标志或水印。
```

## 编辑格式示范

假设用户已将上一例的实际成图作为图 1 提供，要求仅调整补纸颜色。下面只演示这种输入成立时的交付，不表示已取得图片或验证保留效果。

建议画幅：沿用原图｜保留已有工作台与人物构图。

```text
编辑图 1：只将鱼形纸灯腹部裂口外侧的浅杏色补纸改为柔和的珊瑚红，保留补纸原有尺寸、形状、纸纤维和半透明质感，并让其明暗继续符合原图台灯的照明方向。

保持修灯师的身份、表情、发型、服装、双手姿态与接触位置，保持纸灯竹骨、裂口位置、鱼眼、尾鳍、两个托架、桌面工具和窗外雨景。维持原构图、画幅、画法与整体冷暖关系，不给纸灯其他部分重新配色，不增加文字或物件。
```
