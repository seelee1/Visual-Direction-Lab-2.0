# 交付

同一套创作系统完成设计后，按用户要求交付。没有指定格式时直接呈现具体视觉设计，未指定模型的提示词采用通用画面或镜头描述。

| 用户要求 | 交付规则 |
|---|---|
| 将选定设计转成提示词或其他成稿 | [信息保留](信息保留.md) |
| Anima 提示词 | [Anima](Anima-生图.md) |
| GPT Image 提示词 | [GPT Image](GPT-Image-生图.md) |
| MiniMax-H3 提示词 | [MiniMax-H3](MiniMax-H3-视频.md) |

| 关键帧、分层、分镜等复杂制作交接 | [制作交接](制作交接.md) |

模型文件负责格式、语言与模型能力的交付映射，不包含另一套助手核心，也不触发重新创作。只说图片或动画不等于指定生成模型。实际生成依据用户授权与可用环境执行。

## 从用户意图判断能力

适配文档是已整理的使用依据，不是模型能力的完整白名单。用户无需说出功能名称：先理解希望改变或保留的内容、已有素材及目标结果，再依据对应适配提出有帮助的实现建议。例如“这两段接起来太突然”可能需要补接过渡，“前面缺少交代”可能适合向前补写；先判断实际缺口，不只匹配关键词，也不把建议自动当成已获准改动作品。

文档没有覆盖、描述含糊、可能过时，或看起来不支持但会影响用户目标时，先针对当前问题查对应模型版本及平台的官方指南、接口说明与示例。未收录不等于不支持，官方推荐不等于强制，示例能提交也不等于效果有保证。不要因缺少本地条目就否定需求，也不要反向推定模型什么都能做。

核验后区分：模型有该能力、用户入口是否开放、所需输入和参数、提示词能表达的意图，以及仍需实际验证的效果。明确支持时给出具体用法；有条件支持时说明必要条件；官方明确不支持时说明对应版本或入口范围，并提出保留目标的替代办法。查不到、访问失败或资料相互矛盾时如实说“尚未确认”，不要改写为“不支持”，也不编造字段或控制精度。

只查会改变当前建议或交付的缺口，不为每次普通提示词任务重新调查全部能力。已知信息足够就继续创作；必要的平台信息无法从上下文确定时再简短澄清，其余不受影响的内容继续完成。核验与内容建议不等于生成、上传、安装或其他外部操作授权；实际执行仍依用户请求。
