- [实验配置](实验配置.json)：8 个公开场景、6 条件、每条件 3 次探索性运行，共 144 个待运行请求。
- [探针与评审](探针与评审.md)：尺度/条件/风格变更、反例、探索范围及信息保留；供评审侧使用。
- [运行记录模板](运行记录模板.json)：原始输出、环境、控制条件和评审证据。
- [离线准备程序](准备实验.ps1)：展开输入、随机运行顺序和哈希登记；不联网，不生成模型回答。
- 准备后入口：[准备清单](准备输出/准备清单.json)、[运行顺序](准备输出/运行顺序.json)、[冻结登记](准备输出/冻结登记.json)。

## 条件与控制

C00 普通基线；C10 主动唤起；C01 资料；C11 唤起与资料；B1 领域流程；CD 与 C10 相同唤起但使用无关资料。C01/C11 的同场景资料完全相同；C10/C11/CD 的唤起文字完全相同。CD 的资料字符数与相关资料相同，语言 token 数未测，不能称 token 匹配。

全部使用相同基础角色与输出约定。字数是目标范围，记录实际输出与超限，不能把删到范围后的文本作为原始回答。只有公开知识库中的一般机制摘要进入资料，未提供最终场景方案；但资料与场景有关，不能排除示例引导。更多资料粒度与风格对照留待扩大实验。

主实验只看一份成稿，因此评价的是主动展示的选定表现；显式多方向探针另行比较探索范围。主实验与探针分开报告，不能把不同任务的候选数直接并列。

## 执行顺序

1. 先离线准备并保存配置/哈希，后续修订使用新版本。每个模型单独记录标识、环境、日期及可控参数；无法控制的参数明确列出。
2. 按随机顺序发送，每个请求独立新会话，生成阶段不加载完整项目、原型指令、案例或评审答案。不同模型共享相同请求，但各自运行结果分开。
3. 请求 JSON 是模型无关的角色/内容记录，不保证任何 API 可直接接收。按实际接口映射并保存发送内容；无系统入口的模型改用起始消息时，记为不同加载配置。
4. 原样保存输出/错误，不挑最好样本。超时/失败不补成成功；需要重试时另建记录，并保持原失败。
5. 指派随机评审编号，移除场景以外的条件标签并另存对照键；当前只准备了生成 ID，尚未自动形成盲评包。独立评审实际参与才称盲评，作者自评只称诊断。
6. 按维度和问题片段比较，再执行同任务探针。3 次是探索性规模，不作统计显著或普遍能力结论；确定性配置的相同重复只说明稳定性。

准备清单包含条件键，仅在运行侧保存。不能给评审者同时提供清单与回答再称盲评；回答风格也可能暴露条件，需记录其限制。

T07/T08 尚未指定，保留其过程隔离。T10 为本轮公开形式场景，不能宣称盲测。已公开文本演练见[案例](../09-阶段2案例演练与反例.md)，不计入本实验运行。
