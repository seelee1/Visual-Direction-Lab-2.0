# v0.3 激活能力评估

状态：协议与公开开发输入已准备，独立运行 0 次，视频验证 0 次。它们与研究资料中的 v0.1 冻结实验分开，不改写旧实验条件。

## 评估问题

新包是否帮助模型主动调用更多有价值的视觉知识？方案是否具体发展、实质多样、相互协调，并保留到最终表达？效果更丰富但艺术更差也可能发生，必须保留这种结论。

不能根据某次没有出现一个现象就断言模型不知道它；不能根据输出长、术语多或命中入口多就推断增益。最终选用的内容也不能证明模型内部探索了多少可能性。

## 可执行对照

每个公开场景使用相同模型、输出要求和可访问工具，在互相独立的新会话比较以下条件。起始版本至少重复三次用于观察波动；不宣称这种规模足够做统计结论。

| 条件 | 所提供材料 | 目的 |
|---|---|---|
| B0 | 用户要求与统一输出约定 | 观察常规输出 |
| A0 | B0 加当前核心指令 | 看主动调用责任是否有贡献 |
| A1 | B0 加完整基础版，核心指令不重复 | 看广域激活资源是否有额外贡献 |
| A2 | B0 加完整扩展版，基础版与核心指令不重复 | 看更具体的机会与关系入口是否有增益或副作用 |

以上条件在材料长度和内容上不同，属于整包效果比较，不能直接解释为某个机制的净因果效应。若要定位资源效应，另做相近输入长度的相关资源/无关资源控制并记录实际 token；若要控制输出长度，补做相近长度的成稿比较，不能只看自然长度。

统一主交付要求：“只交付一份可独立理解的连续视频提示词，300–500 个中文字符，不展示方案列表或分析。遇到要求冲突可以简短说明。”先按同一要求比较，再另开不限长度的实用性测试，避免字数规则被永久写进创作助手。

输入见[公开开发场景](v0.3-公开开发场景.md)，机器可读输入见[场景配置](v0.3-公开场景.json)。探索范围另测：使用相同场景和原条件，在新的独立会话要求“提出三种观看重点或表现关系实质不同的艺术方案，每种简短说明核心可见变化”。三种仅是实验任务的统一要求，不是运行时固定候选数量。

## 分开评估

| 维度 | 需要引用的输出证据 | 不能替代它的指标 |
|---|---|---|
| 调用范围 | 主动想到的有效表现族，按机制合并而非拆步骤计数 | 术语、物体或效果数量 |
| 展开程度 | 对象、变化、先后、状态和关键条件明确 | 长篇原理解释 |
| 方案差异 | 观看证据、关系组织或时间/形式规则改变 | 换灯色或增加颗粒 |
| 协同 | 动作、材料、光影、空间或时间之间有实际关系 | 同时提及多个领域 |
| 艺术适合度 | 贴合要求、形式贡献、节奏与取舍的具体理由 | “更丰富所以更好” |
| 迁移与边界 | 条件变化后重选或重译，能解释何处不成立 | 原案同义改写 |
| 转换保留 | 核心关系在最终提示词中的明确去向 | 设计阶段写过即可 |

先记录硬问题：违反用户约束、核心接触/空间矛盾、不可辨的核心细节、无意混用真实与图形规则。逐维度记录“缺失/只提及/展开/形成关系”和文字理由，允许不适用；不合成掩盖严重问题的总分。审美偏好可以分歧，记录理由。

新包可能将“主体保持＋环境运动”“差异响应”“间接证据”变成新模板。统计这些组织的重复，不因它们出现在资源中就给予高分；比较它们在不同场景的真实贡献。

## 运行与记录

记录模型完整名称与版本、时间、实际装载内容、源文件哈希、工具和参数、完整输入与原始输出、请求失败与重试、评审依据。不采集隐藏思考，不假装可见内部知识调用。

评审侧先隐藏条件标签，可行时随机排序并请独立评审。公开开发场景不能成为真正未见的保留集；后续版本冻结后再建立未示范场景。不能把本协议或预期诊断加载到主生成条件，否则会泄漏目标。

文本评审只判断设计与表达。实际视频另记录生成模型、控制方式、种子与制作过程，分别定位艺术、转换、执行失败。没有实际输出不填写模型得分，更不能把本项目的手写示例当受测结果。
