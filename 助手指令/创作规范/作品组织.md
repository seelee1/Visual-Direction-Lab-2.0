# 作品组织与设计延续

用于把创作能力汇成一个作品自己的设计，并支持继续发展、局部修改和不同交付。这里保存作品内容与选定关系，不管理生成队列、节点或自动重试。人物、场景、风格、分镜等专业发展仍调用原有表现资源，不重复建立知识库。

## 随作品复杂度组织

一张插画或一个短镜头可以直接完成，用一份设计描述保留重要关系，无须创建设定书、编号或多个文件。继续修改时，在已有设计上更新。

多镜头、漫画、系列或持续创作需要共同依据时，再逐步维护作品概况、相关设定和段落／画面设计。只补本次需要的内容；未设计部分可以留待展开，不能把规划占位符说成已完成作品。实际组织按媒介选择，人物与故事不是所有作品的必需项。

## 一个作品自己的设计依据

| 内容 | 保存什么 | 不应混入什么 |
|---|---|---|
| 创作方向 | 主题、观看体验、媒介、用途、篇幅或时长及画幅；明确要求与选择 | 自动补全的商业目的、情绪或制作限制 |
| 艺术语言 | 形体、线色影形、材料表现、空间与节奏中真正决定作品的规则 | 只有风格名称的清单或每场完全相同的调色 |
| 人物、场景与道具 | 相关身份、形态、空间结构、可变状态；参考各自负责的部分 | 从参考自动继承的全部原设或无用的完整世界观 |
| 场景、镜头、漫画页或系列幅 | 当前实际设计、观看职责、前后连接和共享设定引用 | 把不同媒介单元机械一一换算 |
| 当前决定与待定项 | 用户要求、当前选定方案、必要的开放问题及备选方向 | 把未选候选或生成偶然结果当成正式设定 |
| 输出版本 | 从哪份设计转出的提示词、分镜说明或交接内容及目标用途 | 用最新提示词替代全部作品设计 |

已选方案可以由模型在授权创作中直接作出，不要求用户逐项审批。说明应如实区分用户指定与模型选择；用户后续修改优先。参考信息不足时不能声称已经观察或核对。

## 延续与修改

继续一个作品时先取得相关的当前设计，不重新发明身份、布局或已建立事件。只读有关设定与当前单元，不默认把所有项目资料装入上下文。尚未设计的后续可自主发展；拿不到原设定时，明确缺失，不把新猜测冒充旧决定。

局部修改先确定改变了哪一关系，再追踪实际影响。例如改左手持物可能影响姿态、遮挡和后续交接；改光源方向可能影响影形、反射和观看重点。修改颜色未必影响剧情，改变画法也不自动重写人物身份。更新相关设计与受影响的交付，未受影响的部分保留。

探索新方向与修订当前方向分清。备选方案不自动覆盖当前作品；用户选定或要求直接改造时再更新。废弃方案仅在仍有比较价值时保留，不要求每次维护完整历史。

生成图片或视频可以提供观察反馈，但不是自动成为新设定。区分画面设计不足、转换遗漏、模型误读与用户更喜欢生成变体；只有被采纳的变化才回写作品。例如模型把鱼形纸鸢画成鱼，不据此把作品道具改成活鱼。

## 按需要交付

没有指定输出时，直接给出当前作品的具体设计。简单任务自然成稿；整部作品给整体方向和各单元的实际内容，细节按请求覆盖，不只留下目录与待办。

用户可以继续要求人物设计、场景设计、某一镜分镜、关键画面、图像／视频提示词或制作说明。每项交付都从同一份相关作品设计出发，转换格式不暗中改变作品。分镜可以先于某个镜头细节完成，静态造型也可以反过来启发剧情；组织支持往返发展，不规定唯一流水线。

交付给另一个 agent 或生成工具时，写清本次需要的身份、空间、状态与参考职责，使其可独立理解；不依赖对方读取先前聊天。默认完整表达选定设计，用户要求精简或重构时再处理。模型适配按实际目标另读，设计中心不要求选择模型才能工作。

## 保存方式

作品可以在会话中维护；需要长期保存或跨 agent 使用时，按用户指定的位置保存一份当前设计。小作品一份文档即可，复杂作品需要时再分设定与场景／分镜，用一个简短入口说明当前采用的版本和文件关系，不预建空目录。

作品资料属于具体创作，不默认写入本项目的助手指令、表现资源、参考资料或测试记录。用户未指定外部位置时可在当前工作目录保存明确命名的创作交付，并告知位置；不因此同步到 GitHub 或云盘。用户已授权的保存和同步按对应范围执行。更新设计后可保留有价值的旧版，明确旧交付是否仍适用；不声称会话记忆或文件能自动更新其他 agent。
