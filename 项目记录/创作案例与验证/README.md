# 案例与验证

## 有用的结论

资源可以帮助模型想到具体的视觉关系，但加载更多资料并不稳定地改善设计。支撑、连接、轴向、空间与可见性仍可能冲突；提示词转换也可能保留构思中的错误。应分别观察构思、转换和实际生成，不把细节多或文本长当作作品好。

## 实际调用验证的记录方法

结构检查回答“能否沿链接到达”，实际调用验证回答“Agent 是否找到、理解并用在当前任务中”。只有真正执行任务后才建立该次记录，不预建空样本或未执行计划。

每次实际验证保留：

- **输入与环境**：完整用户任务、当时系统来源版本或哈希、已知执行模型与环境、起始上下文包含哪些材料；未知项如实标注。复用当前维护会话时注明已有背景，不能称为全新会话测试。
- **可观察调用轨迹**：按实际顺序记录搜索范围、取得的文件及章节或行段、是否完整／截断／失败、是否来自已有上下文。使用工具返回或可见记录作依据，不索取或保存隐藏思考，也不以事后回忆冒充逐步轨迹。
- **原始结果**：保存完整原始设计、实际交付及用户反馈；发生压缩时同时保留压缩前后文本，不能只存一段成功摘要。
- **使用与代价**：把实际读取内容与输出中的具体关系对应起来，记录哪次读取解决了什么、哪些未发现明确用途、哪里重复读取或走了弯路。无法从可见证据确定贡献时写“未确定”，不推断模型内部因果。
- **遗漏与检查**：分别记录要求遗漏、条件冲突、关系丢失、误读资料、历史答案混入和有价值的自主设计；不以文件数少、引用多或命中术语作为通过标准。

比较两种调用方式时保留各自的实际输入、上下文和结果，说明任务是否相同、是否重复、评审是否知道条件。没有对照只能作诊断，不能把一次顺利使用说成稳定提升；文本使用、艺术质量与生成执行分别判断。资料未被使用也不自动代表无价值，需结合本次任务需要。

方法参考用户提供的 [DSH 分支调用演练](https://github.com/seelee1/Visual-Direction-Lab-2.0-dsh/blob/86903511e761f424fe14628e5b59e498508cd392/记录/创作案例与验证/子agent-五项知识测试.md)：其记录揭示静态任务的规则可达性与实际阅读范围问题。这里吸收观察真实调用的做法，不采用固定“主 1＋补 1”限制；外部演练不计入本项目测试数量，也不证明当前版本有效。
